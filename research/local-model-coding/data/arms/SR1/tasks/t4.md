# t4 — The consultant check on Kimi (`AKimiConsultantCheckTests`)

## Goal
Prove that `coai-mcp --check-consultant` runs one Kimi turn as a consultation does: in a COPY of the check's scratch repository, on a ONE-SHOT owned home
`<homes root>\coai-vh\<8>\kh-<10 hex>` (a junction to the person's sign-in inside), and disposes that home JUNCTION-FIRST on every ending — answered, failed,
cancelled — and in the root-less shape (settings built by hand, no homes root). Delivers **S5.5.1, S5.5.2, S5.5.3, S5.5.4**.

Know this first (decision 1 of E5.5): the check has NO new branch to write. It already copies for a runtime with `NeedsASanitisedSnapshot` and reserves a
one-shot home for a runtime with a `HomesFolder`; `KimiConsultant` (E5.4) declares both, and E5.3 made the disposal junction-first. So these tests are
expected GREEN on arrival. Your work is the four tests, each given TEETH by a temporary break. Change production code ONLY if a test is red for a
production reason you can show; then the fix goes in `ConsultantCheck.cs` / `ConsultCheckScratch.cs` (the only production files you may touch) and the
summary says what and why.
