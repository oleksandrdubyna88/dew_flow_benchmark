Another author fills the method bodies after you, and you polish the result in a later step. In this step you write the
skeleton only.

- **Write completely:** every new test class and test method with the exact scenario name, its attributes, fixtures, fields
  and usings; every new or changed production signature, type and constant; the JSON rows and vectors; the TS table
  regenerated by its generator. Rows, vectors and tables are data, so you write them in full.
- **Never write a method body longer than 3 lines.** Every such body (test bodies, production bodies, new helper methods
  alike) is a FILL region:

  ```csharp
  // QWEN-FILL-BEGIN <id> <test|prod>
  // What the body must do, step by step: which existing types, members and helpers it calls (exact names), the edge cases,
  // and for a test its Arrange / Act / Assert, the exact assertion, and why it fails before the change.
  throw new NotImplementedException("<id>");
  // QWEN-FILL-END <id>
  ```

  In TypeScript the placeholder is `throw new Error('<id>');`. `<id>` is short and unique (for example `s556-launch`).
  `test` marks the body of a test method or a test helper; `prod` marks production code. One region per method body, each
  no bigger than about 80 lines of code.
- **For every region, write its context pack** to `/home/jinx/git/coai-exp/vllm/work/{{ARM}}/regions/<id>.md`: the exact
  signatures, copied from the repository, of every existing type, constructor, property, method and helper the body needs
  (with namespaces), and a short similar existing test when there is one. The filling author cannot read the repository:
  what is not in the file or in the pack does not exist for it. In earlier drafts, wrong names of existing APIs inside
  bodies were the most common defect.
- The skeleton must **build**: run the build. Do not run the tests (the placeholders throw). Commit the skeleton.
- Never mention the filling author or a local model in code or commit messages.
